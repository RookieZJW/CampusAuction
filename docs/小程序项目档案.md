### W3 核心机制（论文素材，全部实测）

1. **双层出价校验**：Redis Lua 原子脚本（`auction:bid:{id}` HASH + check-and-set）→ MySQL 乐观锁（`WHERE version=? AND current_price<?`，冲突重试 3 次）；Redis 不可用自动降级 DB 单层；落库失败回写 Redis。
2. **防狙击**：末 5 分钟出价 → endTime=now+2min，extend_count 上限 3（实测 extended=true 返回）。
3. **保证金**：每场每用户首次出价冻结 1000 分（SQL 原子扣减 `balance>=deposit` 防透支），流水入 t_account_log；结算时落标者 UNFREEZE（实测 user4: 9000→10000）。
4. **定时结算**：@Scheduled 30s 扫描 + Redis SETNX 分布式锁 + CAS(ONGOING→SETTLING) + t_order.auction_id 唯一索引三重幂等；实测自动 FINISHED + 建单 AU202611131924565563 + 通知双方。
5. **实时刷新**：/live 只回 4 字段；前端 3 秒局部 setData + 振动反馈；onHide 暂停轮询。

### W4 业务闭环机制（论文素材，全部实测）

1. **订单交割**：结算建单（PENDING_TRADING）→ 双方约定地点（通知对手方）→ 买方确认交割（CAS 更新 + 解冻买方保证金 + 买卖双方信用 +2 + 双方通知）→ COMPLETED。
2. **违约处理**：OrderTimeoutTask 每小时扫描创建超 48h 的 PENDING_TRADING 订单 → CAS 置 CANCELLED → 没收买方保证金并记 DEDUCT 流水 → 信用 -10（`GREATEST(credit_score-10,0)` 防负数）→ 双方通知。实测：订单 2 于 19:50:47 自动取消。
3. **双身份鉴权**：用户 token subject=openid，管理员 token subject=`admin:{id}`；AuthInterceptor 对 `/api/v1/admin/**` 前缀强制校验管理员身份，普通用户 token 被拒。
4. **后台统计**：/admin/stats 聚合 8 项指标 + 类目成交分布（关联 t_category 取真实类目名）；分页接口统一 `page/size`（size 上限 50）。

### W5 机制（论文素材，全部实测）

1. **AI 定价双通道**：DeepSeek chat/completions（temperature 0.2，要求严格 JSON，8s 超时）→ 解析失败/未配 Key/异常时自动降级「分类基准价 × 成色系数」规则估价（区间 [0.6,1.2] 倍）；RestClient 超时 3s 连接/8s 读。Key 仅存环境变量或 local.yml。实测降级通道：教材×九成新 → 12~24 元。
2. **互评幂等**：t_review 的 uk_order_from 唯一索引 + 提前查询双保险；仅 COMPLETED 订单、仅交易双方、评价后通知对方（type=REVIEW）。
3. **举报闭环**：同人同对象 PENDING 幂等拒绝；管理端 CAS 处理（PENDING→RESOLVED/DISMISSED）；RESOLVED 扣被举报方（ITEM 举报→卖家）信用 -20 + GREATEST 防负数 + 流水 + 双方通知（type=REPORT）。实测：卖家 100→80、举报人与被举报人均收到通知。
4. **收藏**：uk_user_auction 唯一索引 + toggle 语义；详情页 check 回显心形状态。

### 技术坑位备忘（收尾阶段新增）

-1. **2026-11-15 开发者工具框架层报错**：`WAServiceMainContext.js Cannot read properties of null (reading 'screenHeight')`（工具 2.02.2608080 / lib 3.17.4）。全仓 Grep 确认业务代码**未调用任何设备信息 API**（只读 `wx.getStorageSync`），故为工具侧/基础库灰度版问题。处理：`project.config.json` 与 `miniprogram/project.private.config.json` 的 `libVersion` 由 `latest`/`3.17.4` 固定为本机已下载的稳定版 `3.17.2`；配套「完全退出工具→重开→清缓存」；仍报错则重置模拟器设备型号/窗口尺寸。以微信官方最新规则为准。

0. **2026-11-15 真机点登录报「登录失败」根因**：微信 `code2session` 成功响应为 `{openid, session_key, unionid}`，**没有 errcode**；旧判断 `errcode == null → 失败` 把成功当成失败抛 3008（日志里能看到真实 openid）。已改为主判据「openid 非空且 (errcode==null 或 0)」，并给 `WxSession.sessionKey` 加 `@JsonProperty("session_key")` 与 `@JsonIgnoreProperties`；成功日志对 openid 脱敏。桩测试验证成功/失败两分支均通过。

6. **2026-11-16 详情页显示「距结束 已结束」但后台是「进行中」**：并非状态不一致，`status` 一直是 `ONGOING`。根因是后端 VO 用 `LocalDateTime.toString()` 输出 ISO 格式 `2026-11-17T04:02:34`（带 `T`），而小程序两处倒计时用 `new Date(endTime.replace(/-/g,'/'))` → 拼成 `2026/11/17T04:02:34` → `Invalid Date` → `getTime()=NaN` → `NaN > 0` 为 false → 文案回落成「已结束」；`NaN <= 300000` 也为 false，所以连 urgent 标红都失效。其它展示字段（`bidTime`/`createTime`）和后台 `fmtTime()` 都写了 `.replace('T',' ')`，唯独倒计时漏了，才出现"一处正常一处错"。

7. **2026-11-16 分类标签不生效（列表与标签不对应）**：`AuctionServiceImpl.pageList()` 虽接收 `categoryId`，但 `LambdaQueryWrapper` 只加了 `status=ONGOING`，参数从未使用 → 点任何分类都返回全部在拍拍品。根因是类别字段在 `t_item.category_id`，`t_auction` 没有该列，当初写分页时漏了关联过滤。
