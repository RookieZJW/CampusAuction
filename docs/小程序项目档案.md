### 登录机制（2026-11-17 最终版，论文素材）

1. **新用户一步建号**：进小程序弹资料卡，一屏内选头像（`chooseAvatar`）、填昵称（`input type=nickname`）、授权手机号（`getPhoneNumber`）、勾协议，点「登录」一次性提交。后端 `POST /auth/register` 收 wxCode+phoneCode+nickname：code2Openid + getPhoneNumber → 手机号查账号（打通）→ 无则 openid 兜底注册 → 写昵称手机号 → 签发 JWT。前端拿到 token 后再上传头像（`/upload/image` 需鉴权）+ `PUT /users/profile` 更新头像，用户只点一次登录、无感。
2. **老用户免登录**：`app.js` 的 `restoreLogin()` 同步从本地恢复 `userInfo`，首页 `onShow` 调 `tryPromptLogin()` 判断有登录态则不弹；token 异步校验失败才清空并补弹一次。
3. **账号锚点不变**：`t_user.openid` 仍非空唯一，JWT subject / AuthInterceptor 一行未改。手机号只是「登录凭证」，同一手机号在任何微信登录进同一账号。
4. **邮箱登录已彻底删除**：前端无邮箱入口；后端删除 `/auth/email/code`、`/auth/login/email`、`EmailCodeService` 及 3 个 DTO、`application.yml` 的 `auth.email.*`；数据库 `t_user.email` 列与 `uk_email` 索引已 drop（迁移脚本 `sql/migration/2026-11-17-multi-login.sql` 最终版）。
5. **安全与合规**：`WebConfig` 白名单放行 `/auth/login` + `/auth/register`；手机号明文、`session_key`、`access_token` 不写日志不下发；头像昵称手机号均用户主动填写/授权，不静默获取；协议不默认勾选。


### W3 核心机制（论文素材，全部实测）

1. **双层出价校验**：Redis Lua 原子脚本（`auction:bid:{id}` HASH + check-and-set）→ MySQL 乐观锁（`WHERE version=? AND current_price<?`，冲突重试 3 次）；Redis 不可用自动降级 DB 单层；落库失败回写 Redis。
2. **防狙击**：末 5 分钟出价 → endTime=now+2min，extend_count 上限 3（实测 extended=true 返回）。
3. **保证金**：每场每用户首次出价冻结 1000 分（SQL 原子扣减 `balance>=deposit` 防透支），流水入 t_account_log；结算时落标者 UNFREEZE（实测 user4: 9000→10000）。
4. **定时结算**：@Scheduled 30s 扫描 + Redis SETNX 分布式锁 + CAS(ONGOING→SETTLING) + t_order.auction_id 唯一索引三重幂等；实测自动 FINISHED + 建单 AU202611131924565563 + 通知双方。
5. **实时刷新**：/live 只回 4 字段；前端 3 秒局部 setData + 振动反馈；onHide 暂停轮询。

### W4 业务闭环机制（论文素材，全部实测）

1. **订单交割**：结算建单（PENDING_TRADING）→ 双方约定地点（通知对手方）→ 买方确认交割（CAS 更新 + 解冻买方保证金 + 买卖双方信用 +2 + 双方通知）→ COMPLETED。
2. **违约处理**：OrderTimeoutTask 每小时扫描创建超 48h 的 PENDING_TRADING 订单 → CAS 置 CANCELLED → 没收买方保证金并记 DEDUCT 流水 → 信用 -10（`GREATEST(credit_score-10,0)` 防负数）→ 双方通知。实测：订单 2 于 19:50:47 自动取消。
3. **双身份鉴权**：用户 token subject=openid，管理员 token subject=`admin:{id}`；AuthInterceptor 对 `/api/v1/admin/**` 前缀强制校验管理员身份，普通用户 token 被拒。
4. **后台统计**：/admin/stats 聚合 8 项指标 + 类目成交分布（关联 t_category 取真实类目名）；分页接口统一 `page/size`（size 上限 50）。

### W5 机制（论文素材，全部实测）

1. **AI 定价双通道**：DeepSeek chat/completions（temperature 0.2，要求严格 JSON，8s 超时）→ 解析失败/未配 Key/异常时自动降级「分类基准价 × 成色系数」规则估价（区间 [0.6,1.2] 倍）；RestClient 超时 3s 连接/8s 读。Key 仅存环境变量或 local.yml。实测降级通道：教材×九成新 → 12~24 元。
2. **互评幂等**：t_review 的 uk_order_from 唯一索引 + 提前查询双保险；仅 COMPLETED 订单、仅交易双方、评价后通知对方（type=REVIEW）。
3. **举报闭环**：同人同对象 PENDING 幂等拒绝；管理端 CAS 处理（PENDING→RESOLVED/DISMISSED）；RESOLVED 扣被举报方（ITEM 举报→卖家）信用 -20 + GREATEST 防负数 + 流水 + 双方通知（type=REPORT）。实测：卖家 100→80、举报人与被举报人均收到通知。
4. **收藏**：uk_user_auction 唯一索引 + toggle 语义；详情页 check 回显心形状态。

### 用户资料与隐私机制（2026-11-16 新增，论文合规章节素材）

1. **身份边界**：`wx.login` 只换 `openid`，不自带头像/昵称/手机号；`wx.getUserInfo` / `wx.getUserProfile` 已废弃，项目未使用。
2. **头像昵称填写能力**：`button[open-type=chooseAvatar]` + `input[type=nickname]`，基础库 2.21.2+；`chooseAvatar` 只返回临时路径，须走 `/upload/image` 持久化后再提交 `/users/profile`。昵称在 blur 时由微信做内容安全检测。
3. **手机号快速验证**：`button[open-type=getPhoneNumber]` 回调给动态 `code`（5 分钟、一次性，与 `wx.login` 的 code 不通用）→ 服务端 `getAccessToken()`（内存缓存 2h、提前 5min 刷新、`synchronized` 防重复获取）→ `wxa/business/getuserphonenumber` 换 `purePhoneNumber`。`access_token` 只在服务端使用，绝不下发前端、不落日志。
4. **隐私合规**：`app.json` 开 `__usePrivacyCheck__`；进页先 `wx.getPrivacySetting`，用 `wx.onNeedPrivacyAuthorization` 接管授权弹窗；同意走 `open-type=agreePrivacyAuthorization` 并 `resolve({buttonId,event:'agree'})`，拒绝也允许继续浏览，不强制授权。登录页隐私指引可点开（`wx.openPrivacyContract`）。
5. **数据安全**：`profileMap()` 只回本人三项资料，`Map.of` 不接受 null 故空值转空串；手机号明文不写日志（只记 user id）；`wx.mock=true` 时明确拒绝调 `access_token` / 手机号接口，避免写入假数据。

### 技术坑位备忘（2026-11-21 手机号 412 新增）

- **点登录报「微信服务暂不可用」根因 = 微信网关回 412 Precondition Failed**：日志证据 `code2session 成功 openid=ooig****us6g` → `access_token 刷新成功` → `换取手机号网络异常：412 Precondition Failed: [no body]`。不是网络/AppSecret/隐私指引问题。

- **错误提示改进**：`getPhoneNumber()` 单独 catch `HttpClientErrorException`，日志保留 HTTP status + body，区分 412/401/429，避免一律兜底成「微信服务暂不可用」这种查不出问题的提示。
- **验证**：编译通过；服务已重启（日志 `Started ... in 4.54s`）；curl 直连微信接口 HTTP 200 对照证明 Content-Length 是关键。**真机完整链路待用户复测**（真机点登录换真 code）。
