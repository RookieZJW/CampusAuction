# 小程序项目档案 — 校园在线拍卖系统

> 本档案用于跨会话恢复项目上下文。每次开发交付后更新。**禁止写入 AppID、密钥等敏感值明文。**

## 一、项目概况

| 项 | 内容 |
|---|---|
| 项目名称 | 基于微信小程序的校园在线拍卖系统（CampusAuction） |
| 项目性质 | 本科毕业设计（含论文、开题报告、外文翻译、中期检查、答辩） |
| 主体类型 | 个人主体（**无法开通微信支付**，故采用虚拟保证金方案） |
| 上线策略 | 不提审上线，仅开发版/体验版演示（"拍卖"属限制类目，需《拍卖经营批准证书》） |
| AppID 环境 | 测试环境已配置（值不入档）；正式环境未使用 |
| 当前阶段 | **阶段 1 需求确认 / 阶段 2 技术方案（已完成计划书）** |
| 计划周期 | 8 周（1-2 个月，时间紧张，执行 P0/P1 砍留策略） |

## 二、技术栈（已定）

| 层 | 技术 |
|---|---|
| 小程序端 | 微信原生框架 + TDesign/Vant Weapp，基础库 ≥2.30.0（以官方文档核实） |
| 服务端 | Spring Boot 3.2 + MyBatis-Plus 3.5 + JWT(jjwt) + Knife4j |
| 数据 | MySQL 8.0（金额用 int 分）+ Redis 7（缓存/锁/预校验） |
| 管理后台 | Vue 3 + Vite + Element Plus |
| AI | DeepSeek 或通义千问 API（Key 仅存服务端环境变量） |
| 部署 | 云服务器 + Nginx + Docker Compose；演示免备案（关闭域名校验） |
| 压测 | JMeter 5.6 |

> ⚠️ **选型待确认**：用户 2026-11-13 提出"后端改用微信云开发是否可行"。已给出适配方案（计划书附录 B）。当前默认仍为 Spring Boot；若确定切换，需同步修改：部署方式、鉴权（OPENID 免 code2session）、出价实现（version 条件更新）、结算（定时触发器）、后台部署（静态托管/HTTP 访问）。**决策未定，勿按云开发写代码。**

### wx API 计划使用

| API | 用途 | 备注 |
|---|---|---|
| `wx.login` | 静默登录取 code | code 必须发服务端换 session_key |
| `wx.getUserProfile` / 头像昵称填写能力 | 获取昵称头像 | 需用户点击触发 |
| `wx.chooseMedia` + `wx.compressImage` | 选图 + 压缩 | 限制 3 张 |
| `wx.request` | 网络请求 | 开发版关闭域名校验 |
| `wx.requestSubscribeMessage` | 开拍/成交通知（P2） | 一次性订阅，需模板 |
| `msgSecCheck` / `imgSecCheck` | 内容安全（服务端调用） | 发布必接 |

## 五、数据表清单（14 张，设计已定稿）

`t_user`、`t_admin`、`t_category`、`t_item`、`t_auction`、`t_bid_record`、`t_order`、`t_account_log`、`t_credit_log`、`t_review`、`t_report`、`t_favorite`、`t_notification`、`t_subscribe`

核心设计：物品与拍卖解耦；拍卖状态机 PENDING→READY→ONGOING→FINISHED/FAILED/CANCELLED；`t_order.auction_id` 唯一索引保证结算幂等；金额 int 存分。
