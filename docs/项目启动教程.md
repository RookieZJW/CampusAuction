## 0. 一页速查（背下这四条命令就够）

> 所有命令在 **Git Bash** 里执行；需要常驻的进程各自开一个终端窗口。

```bash
# ① Redis（本机已装，默认端口 6379）
"D:/Redis-8.6.4/redis-server.exe" --port 6379

# ② Spring Boot 服务端（另一个终端）
cd /e/campus-auction/server && mvn -q -o spring-boot:run > server-run.log 2>&1

# ③ Vue3 管理后台（第三个终端，首次需 npm install）
cd /e/campus-auction/admin && npm run dev

# ④ 微信开发者工具：GUI 手动打开项目根目录 E:/campus-auction
```

**启动顺序不能乱**：MySQL（Windows 服务通常已自启）→ Redis → 服务端 → 管理后台 → 开发者工具。

| 端口 | 进程 | 成功标志 |
|---|---|---|
| 3306 | MySQL 8 | `mysql -uroot -p -e "SELECT 1"` 有输出 |
| 6379 | Redis | `redis-cli ping` → `PONG` |
| 8080 | Spring Boot | 浏览器打开 `http://localhost:8080/doc.html` 能看到 Knife4j 接口文档 |
| 5173 | Vite | 浏览器打开 `http://localhost:5173` 能看到管理后台登录页 |

## 2. 分步启动（含每一步的成功标志与失败处理）

### 第 1 步：MySQL

本机 MySQL 8 通常是 Windows 服务，开机自启，无需手动启动。

```bash
# 检查
"/c/Program Files/MySQL/MySQL Server 8.0/bin/mysql.exe" -uroot -p -e "SELECT VERSION()"
```

- 没起来：`services.msc` → 找 MySQL 服务 → 启动；或用 WAMP 面板启动。
- 报 `Access denied`：核对 `application-local.yml` 里的密码与命令行输入是否一致。

### 第 2 步：Redis

```bash
"D:/Redis-8.6.4/redis-server.exe" --port 6379
```

- 这个窗口**不要关**，关了 Redis 就停。
- 成功标志：窗口显示 Ready to accept connections；另开终端 `redis-cli ping` → `PONG`。
- ⚠️ 坑：Git Bash 给 `.exe` 传 `D:/xxx.conf` 这类路径参数会被 MSYS 改写导致启动失败，**本机直接不带配置文件启动**即可（默认无密码，仅监听本机）。

> Redis 挂掉时系统仍能出价——`AuctionCacheService` 有降级探测，会自动退回 MySQL 乐观锁单层校验，功能不中断。但演示并发亮点时务必让 Redis 活着。

### 第 3 步：Spring Boot 服务端

```bash
cd /e/campus-auction/server
mvn -q -o spring-boot:run > server-run.log 2>&1
```

- `-o` 离线模式（依赖已缓存，启动更快）；`-q` 静默；日志写到 `server-run.log`（已 gitignore）。
- 首次启动约 5-10 秒；看到日志里 `Started CampusAuctionApplication` 即就绪。
- 成功标志：`curl http://localhost:8080/api/v1/categories` 返回 `{"code":0,...}`。
- 接口文档：`http://localhost:8080/doc.html`（Knife4j，答辩演示可展示）。

**启动失败速查**：

| 现象 | 原因 | 处理 |
|---|---|---|
| `Communications link failure` | MySQL 没起或密码错 | 回到第 1 步 |
| `Address already in use: 8080` | 端口被占用（多半是上次没关干净） | `netstat -ano \| grep 8080` 找 PID → `taskkill //PID <pid> //F` |
| `Cannot connect to Redis` | Redis 没起 | 回到第 2 步（服务端能启动但出价会降级） |
| 编译报错 | 代码改动未编译 | `mvn -o clean compile` 看具体报错 |

### 第 4 步：Vue3 Web 管理后台

```bash
cd /e/campus-auction/admin
npm run dev
```

- 访问 `http://localhost:5173`，账号 `admin / admin123`（演示环境默认账号）。
- `vite.config.js` 已配置 `host: '0.0.0.0'` 与 `/api`、`/uploads` 代理到 `127.0.0.1:8080`，所以 `localhost` 和 `127.0.0.1` 都能打开，无需处理跨域。
- 成功标志：登录 → 数据看板出现 8 项指标（注册用户数、成交总额等）。
- 生产构建：`npm run build`，产物 `admin/dist/`（部署见《部署文档.md》4.7）。

### 第 5 步：微信开发者工具（GUI，需手动）

1. 打开**微信开发者工具** → 导入项目 → 目录选 `E:/campus-auction`；
2. AppID 已在项目配置中，无需手填；
3. **关键**：详情 → 本地设置 → 勾选
   **「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」**；
4. 点「编译」，模拟器应显示拍卖大厅列表。
5. **调试基础库固定为 `3.17.2`**（已在 `project.config.json` 与 `project.private.config.json` 中写死）。
   不要用 `latest` / 3.17.4 等灰度版——开发者工具在基础库 3.17.4 下会出现框架层报错
   `WAServiceMainContext.js: Cannot read properties of null (reading 'screenHeight')`。
   若工具里仍显示 3.17.4：详情 → 本地设置 → 调试基础库 → 选 `3.17.2`（本机已下载，无需联网）。

> 📌 不勾选会报 `request:fail url not in domain list`。原因是后端是 `http://localhost`，不是备案 HTTPS 域名；
> 本项目**不提审上线**，仅开发版/体验版演示，所以这个开关是设计内的，不是偷懒。
> 微信登录能力官方文档：小程序官方文档「登录」/「登录态与 session」章节
> <https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html>
> 相关基础库版本要求与平台规则**以微信官方最新文档为准**。

**真机预览**：工具栏「预览」→ 手机扫码 → 手机上需打开调试模式（右上角胶囊 → 开发调试），否则同样会因域名校验失败。

## 3. 启动后自检（复制这一段一次跑完）

```bash
for p in 3306 6379 8080 5173; do
  (echo > /dev/tcp/127.0.0.1/$p) >/dev/null 2>&1 && echo "$p ✅" || echo "$p ❌ 未监听"
done

curl -s http://localhost:8080/api/v1/categories | head -c 80; echo
curl -s "http://localhost:8080/api/v1/auctions?page=1&size=1" | head -c 200; echo
curl -s -o /dev/null -w "后台首页 HTTP %{http_code}\n" http://localhost:5173/
```

| 检查点 | 期望 |
|---|---|
| 四个端口 | 全部 ✅ |
| 分类接口 | `{"code":0,...}` 且含「教材书籍」 |
| 拍卖大厅 | `total >= 1`，有进行中拍品与倒计时 |
| 后台首页 | HTTP 200 |
| 管理员登录 | `admin / admin123` 可进看板 |
| 小程序登录 | 点「微信一键登录」后「我的」显示昵称、余额 100 元、信用 100 |

> 若大厅 `total: 0`（所有拍卖都到期结算了），按第 6 节「补演示数据」插一条即可。
> 2026-11-15 启动时已预置一条 2 小时倒计时的「演示用：考研数学复习全书（九成新）」。

## 5. 停止与重启

| 操作 | 做法 |
|---|---|
| 停管理后台 | 在 Vite 终端按 `Ctrl+C` |
| 停服务端 | 在 mvn 终端按 `Ctrl+C` |
| 停 Redis | 在 Redis 终端按 `Ctrl+C` 或 `redis-cli shutdown` |
| 停 MySQL | 一般不用停（Windows 服务常驻） |
| 全部重启 | 按第 2 步顺序再来一遍；**不需要重新初始化数据库**，数据都在 |

> 会话里如果用 `run_in_background` 起的后台任务，重启前先停掉旧任务，避免 `Address already in use: 8080`。

## 6. 常见故障排查表（本项目实测踩过的坑）

| 现象 | 根因 | 修复 / 规避 |
|---|---|---|
| `Address already in use: 8080 / 5173` | 旧进程没退干净 | `netstat -ano \| grep <端口>` → `taskkill //PID <pid> //F` |
| 小程序 `url not in domain list` | 未勾选「不校验合法域名」 | 详情 → 本地设置勾选；真机需开调试模式 |
| 微信登录返回 3008，日志 `40029 invalid code` | code 一次性，已被用过 / 是假 code | 重新点登录由 `wx.login` 生成新 code；正常现象 |
| 微信登录返回 3008，但日志里**有 openid 且 errcode 为 null** | 微信成功响应不带 errcode，旧版后端把 `errcode==null` 误判为失败 | 已修复（以 openid 为成功判据）；重启服务端后重新登录 |
| 控制台红字 `WAServiceMainContext.js … Cannot read properties of null (reading 'screenHeight')` | **框架层/工具侧报错**，不是业务代码（本项目全仓未调用 `getSystemInfoSync` 等设备 API）；多因调试基础库为灰度版或模拟器窗口尺寸未就绪 | ①项目已把 `libVersion` 固定为 `3.17.2`；②**完全退出**开发者工具再重开（避免退出时把 private config 写回 3.17.4）；③工具 → 清除缓存 → 全部清除；④仍报错则切换模拟器设备型号/重置窗口尺寸。规则与版本以微信官方最新文档为准 |
| 微信登录返回 3008，日志 `40125` | AppSecret 不对 | 核对 `application-local.yml`（不贴明文、不提交） |
| 微信登录返回 5000 | 老版本 RestTemplate 未处理 `text/plain` 响应 | 已修复（`MappingJackson2HttpMessageConverter` 追加 text/plain）；若复现看 `server-run.log` 堆栈 |
| 后台页面能开但接口 401/2002 | 管理员 token 失效或用了用户 token | 退出重新登录；`/api/v1/admin/**` 只认管理员 token |
| 后台刷新子路由 404（生产环境） | history 路由没回落 index.html | Nginx `try_files $uri $uri/ /index.html` |
| `127.0.0.1:5173` 打不开但 `localhost` 能开 | Vite 只绑 IPv6 `[::1]` | 已修：`vite.config.js` 设 `host: '0.0.0.0'` |
| 出价一直失败、日志出现 Redis 连接异常 | Redis 没启动 | 启动 Redis；系统会自动降级但并发演示效果打折 |
| 大厅空白 | 所有拍卖都已结束 | 按下方 SQL 补一条演示数据 |
| mysql 命令行中文显示乱码 | Windows 代码页显示问题 | 库内是 utf8mb4，用 `HEX()` 或接口返回验证即可，不用改库 |

## 7. 答辩应急（断网 / 起不来怎么办）

1. **先保住本地链路**：断网不影响本机 4 个进程，只有「微信一键登录」需要联网调微信接口。
   若现场断网，把 `application-local.yml` 的 `wx.mock` 临时改成 `true` 并重启服务端即可离线登录（模拟 openid），**演示完记得改回 `false`**。
2. **演示视频兜底**：提前录好 3 分钟全流程视频， projector/网络出问题时直接放。
3. **后台截图兜底**：`docs/screenshots/` 已有看板、用户管理、举报处理实测截图。
4. **别在现场改代码**：所有演示数据提前造好，现场只点不写。

## 8. 合规与安全提示

- 本项目认证主体为**个体工商户（已微信认证）**，属非个人主体，因此手机号快速验证组件可用（1000 次体验额度）；但本项目仍不接真实支付，采用虚拟保证金 + 线下交割；「拍卖」属限制类目，**不提审上线**，仅开发版/体验版演示。类目资质与审核规范**以微信官方最新规则为准**。
- 微信登录相关：`code` 必须由 `wx.login` 产生并发到服务端换取 openid，`session_key` 绝不下发前端；官方文档路径见第 2 步第 5 节。
- 密钥（数据库密码、AppSecret、AI API Key）只放 `application-local.yml` 或环境变量，**严禁提交 git、写进文档或出现在小程序前端代码**。
- 收集用户信息（**昵称、头像、手机号**）需先在 MP 后台「设置 → 服务内容声明 → 用户隐私保护指引」提交并审核通过，声明对应信息类型；未声明时 `chooseAvatar` / `input[type=nickname]` / `getPhoneNumber` 会被微信禁用。提审还需在「用户隐私保护设置」选择采集用户隐私。相关要求以[微信官方隐私接口文档](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/privacy.html)为准。
- 用户资料链路：`GET/PUT /api/v1/users/profile`、`POST /api/v1/users/phone`；服务端 `access_token` 仅在内存缓存，手机号明文与 `session_key` 均不写日志、不下发前端。
- 演示前若隐私指引尚未审核通过，可不演示「完善资料」页，或不点手机号授权（头像昵称填写能力同样受隐私校验约束）；不影响其余功能演示。
